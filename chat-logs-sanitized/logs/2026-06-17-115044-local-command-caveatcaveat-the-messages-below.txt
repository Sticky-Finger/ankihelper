  关键分支定位

  按 PROJECT_ANALYSIS.md 的目录树，点击通知后的划词组件位于 ui/popup/ 
  分支下，核心是 PopupActivity.java，它编排了以下协作组件：

  - ui/widget/BigBangLayout ——
  文本以可点选「词块」形式呈现（即「BigBang」式分词展示）
  - util/TextSplitter —— 负责把整段文本切成单词列表
  - data/dict/IDictionary —— 查询入口（由 DictionaryRegister 提供具体词典实例）
  - data/plan/OutputPlan —— 决定查到结果后填到哪些 Anki 字段

  与通知文档（CBWatcherService 分析）的衔接点

  通知文档第 113-130 行已经精准指出了「跳转目标」在
  PopupActivity.java:729-735，那里只是入口识别。真正的「划词」逻辑实际上是：

  1. handleIntent() 调 populateWordSelectBox()（第 770 行），但此时
  mTextToProcess 在 Android 10+ 上还是空字符串
  2. 等 Activity 拿到窗口焦点后 onWindowFocusChanged()（第 690 
  行）才真正读取剪贴板内容，再次调用 populateWordSelectBox() 完成分词和首词查询

  结论：通知点击触发的「划词组件」= ui/popup/PopupActivity + 其内部的
  BigBangLayout（词块展示）+ TextSplitter（分词）+
  IDictionary.wordLookup()（查词），全部位于 ui/popup/ 和 ui/widget/
  分支下，并通过 data/dict/、util/ 完成实际查词。

     剪贴板锁定 + PopupActivity 状态保留

     背景

     用户在划词时（PopupActivity
     打开中）想去别处复制「笔记」内容来粘贴，遇到两个问题：

     1. 剪贴板被覆盖：复制的笔记内容替换了 CBWatcherService
     正在监听的剪贴板文本，破坏了划词流程
     2. Popup 被销毁：切到其他 app 后 PopupActivity 被系统销毁（因为 noHistory="
     true"），之前选的词、写的笔记全丢。只能点通知重新进入，但状态已清空

     本功能一次解决这两个问题：添加剪贴板锁定开关 + 让 PopupActivity 可以保活。

     ---
     设计方案

     核心思路

     - 三个入口共享一个锁状态（共享 Settings 中的 clipboard_locked 布尔值）：
       a. 通知栏按钮（下拉通知栏点 🔒/🔓）
       b. PopupActivity 底部锁定按钮
       c. 两者同步，任一入口切换，另一个立即感知
     - 锁定行为：CBWatcherService.performClipboardCheck() 和
     PopupActivity.onWindowFocusChanged() 中的剪贴板读取都检查锁状态
     - 状态保留：移除 noHistory（让 Activity 切走时保活）+ SharedPreferences
     持久化关键字段（兜底）

     交互流程

     用户复制单词 A → 通知 → PopupActivity 展示 A
         ↓
     用户在 Popup 里选中词、查释义
         ↓
     用户点「🔒 锁定」（通知栏或 Popup 底部按钮均可）
         ↓
     用户切到其他 app 复制笔记内容 B
         ├─ CBWatcherService 检测到剪贴板变化 → 检查锁状态 → 已锁定，忽略
         ├─ PopupActivity 因移除 noHistory，进入 onStop 但不销毁（短时间）
         └─ 如果 PopupActivity 被杀（长时间或内存压力）→ onPause 已保存状态
         ↓
     用户回到 Popup（或点通知重新进入）
         ├─ Activity 还活着 → onResume，状态完整保留
         └─ Activity 已销毁 → 新实例从 SharedPreferences 恢复
     mTextToProcess/A、笔记等
         ↓
     用户粘贴 B 到笔记框
         ↓
     用户点「🔓 解锁」→ CBWatcherService 恢复监听

  当前项目的现实约束

  从 CLAUDE.md 看，项目只有 JUnit 4.12（JVM 单测）+ Espresso（设备测试），没有

  Robolectric，否则测试金字塔会塌成只能测纯逻辑或只能跑设备测试

  1. 先引入 Robolectric（build.gradle 加依赖，build.gradle 配置 testOptions { 
  unitTests.includeAndroidResources = true }）
  2. 抽离纯逻辑到 helper 类，对它们做严格 TDD：

  锁定决策
    - PopupStateStore —— 把 tags 序列化/反序列化从 Activity 中分离出来

   很痛苦）：
    - Settings 的 SharedPreferences 读写
    - CBWatcherService 的 intent action 分发
  4. 关键路径用 Espresso 做端到端验证（锁定 → 切走 → 复制 → 切回 → 状态保留）
