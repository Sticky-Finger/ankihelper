● APK 本质上就是一个 ZIP 压缩包，assets/ 目录下的文件会原样保留在 APK
  中，可以直接解压提取。

  步骤如下：

  1. 准备工作

  把 APK 文件复制到一个工作目录，比如 ~/apk_extract/。

  2. 解压 APK

  cd ~/apk_extract
  # 方法一：直接改后缀为 .zip 后解压
  cp your_app.apk your_app.zip
  unzip your_app.zip -d apk_contents/

  # 方法二：直接用 unzip 解压 apk（不改后缀也行）
  unzip your_app.apk -d apk_contents/

  3. 定位数据库文件

  APK 内部结构与项目 app/src/main/ 对应，数据库文件在：

  apk_contents/assets/databases/

  查看有哪些 .db 文件：

  ls -lh apk_contents/assets/databases/*.db

  4. 复制到项目中

  cp apk_contents/assets/databases/collins_v2.db \
     /media/wpw/D/DOCS/Codes/ankihelper/app/src/main/assets/databases/

  cp apk_contents/assets/databases/ode2_v2.db \
     /media/wpw/D/DOCS/Codes/ankihelper/app/src/main/assets/databases/

  如果有其他 .db 文件，也一并复制。

  5. 验证并重新编译

  # 确认文件大小合理（柯林斯约 33MB，牛津约 46MB）
  ls -lh /media/wpw/D/DOCS/Codes/ankihelper/app/src/main/assets/databases/

  # 重新编译
  ./gradlew assembleDebug

  补充说明： assets/
  目录下的文件在打包时不会经过任何编译或加密处理，所以解压出来的 .db
  文件可以直接使用，不需要额外处理。如果 APK 体积很大（几百
  MB），解压会比较慢，也可以只解压需要的文件：

  unzip your_app.apk "assets/databases/*" -d apk_contents/

  这样只会提取 databases 目录下的文件，速度快很多。

● 会的。Android 编译时 assets/ 目录下的所有文件（包括子目录）都会原样打包进
  APK，不做任何过滤。所以如果你把 .zip 备份文件放在
  app/src/main/assets/databases/ 下：

  1. 会被打包进 APK — 增大 APK 体积
  2. 运行时可通过 AssetManager 访问到 — 虽然不会造成功能问题，但属于多余的文件

  建议把备份文件移到项目外面，或者至少移到 app/src/main/assets/
  之外，比如放到项目根目录下的某个备份文件夹里：

  # 移到项目根目录下
  mv app/src/main/assets/databases/backup.zip ./db_backup.zip

● 看了 .gitignore，第 3 行有 *.db 规则，这就是为什么这些文件没被 Git 追踪。

  关于纳入版本控制：

  有两种做法：

  方法一：添加例外规则（推荐）

  在 .gitignore 中加一行排除规则，只允许这个特定目录的 .db 文件：

  # 在 .gitignore 末尾添加
  !app/src/main/assets/databases/*.db

  方法二：删除通用规则

  把 *.db 那行删掉，但这会追踪项目中所有 .db 文件，可能不是你想要的。

  然后执行：

  git add -f app/src/main/assets/databases/*.db
  git commit -m "chore: 恢复本地词典数据库文件"

  ---
  关于版权问题，我必须直说：

  这些词典（柯林斯、牛津）是商业词典，版权归出版社所有。把它们放进 Git
  仓库并公开（比如推到 GitHub），存在明确的法律风险：

  1. DMCA 投诉 — 版权方可以要求平台删除你的仓库
  2. 法律追责 — 虽然个人开发者被起诉的概率低，但风险存在
  3. 平台封禁 — GitHub/Gitee 等平台会根据 DMCA 投诉封禁账号

  合法的做法：

  1. 不要公开这些 .db 文件 — 把它们从 Git 中排除（保持现在的状态），在 README
  中说明"本地词典数据库需要用户自行准备"
  2. 提供下载说明 —
  文档中记录如何从合法渠道获取，或者说明"需要用户从已购买的词典中提取"
  3. 使用开源替代 — 比如 Wiktionary、FreeDict 等开源词典数据

  我的建议：

  既然你已经从 APK 中提取了这些文件并在本地使用，继续把它们排除在 Git 
  之外是最稳妥的做法。你可以在项目文档（比如 docs/setup.md 或 README）中记录：

  ▎ 本地词典（柯林斯、牛津）的数据库文件需要从旧版安装包中手动提取，放入 
  ▎ app/src/main/assets/databases/ 目录后方可编译。

  这样既不侵权，又能让其他开发者知道如何操作。
